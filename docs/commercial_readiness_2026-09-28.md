# 상용화와 실사용 가치: 탐색 결과

기준일: 2026-09-28. 범위: MySQL/PostgreSQL, Windows/macOS/Linux.
코드와 공식 제품 문서를 확인한 기능 탐색에서 시작했고, 아래에 구현·배포 진행을 갱신한다.
사용자 인터뷰나 구매 의향 조사 결과를 주장하지 않는다.

## 현재 완료 수준

안전 복원과 Export/Import 수정은 v2.6.0으로 정식 배포했다. 보호 CI, 설치 자산
10개 해시, macOS 체크섬 4개와 실제 업데이트 확인 경로를 검증했다. 대용량 복원·전환
리허설에서는 활성/백업 테이블 452개의 실제 행 수가 모두 일치했다.

첫 후속 묶음은 직접 연결 창의 응답성이다. 연결과 정리를 백그라운드에서 수행하고
취소된 요청의 늦은 결과를 폐기하며, 연결 테스트 결과 신호도 수정했다. Windows
2,846개, Linux 2,813개 전체 테스트와 macOS 보호 CI가 통과했고 v2.6.1로 배포했다.
네트워크 요청 자체의 강제 중단을 보장하는 기능은 아니며, 정리가 완료될 때까지
앱 종료를 보호한다. SQL 쿼리 취소는 별도 TF-STATUS-112 작업이다.

상용화 전체가 완료된 것은 아니다. TLS/SSH 서버 신원 확인(TF-STATUS-110), 전체 객체
복원 보장(TF-STATUS-111), 취소/큰 결과/실패 복구(TF-STATUS-112), 실제 Mac 및 공급자별
검증(TF-STATUS-008/096/098/109)이 남아 있다.

## 제품 방향 가설

사용자 확인: **개발자·소규모 팀의 일상 DB 작업**이 첫 핵심 사용 대상이다.
기존 제품의 SSH 기반 운영 DB 접근을 주요 사용 맥락으로 삼는다.
추천 가치 제안은 **연결부터 운영 SQL 실행, 변경 확인, 복구 검증까지 한 흐름으로 끝내는 도구**다.
구매 의향이 확인된 결론은 아니며 파일럿 사용으로 검증해야 한다.

이미 있는 SQL 탭, 파일 열기/저장, 자동완성, 히스토리·즐겨찾기, PK 기반 셀 편집,
수동 커밋/롤백, 환경 분류·위험 작업 확인, 스키마 비교를 신규 기능으로 다시 제안하지 않는다.

P2는 기반을 검증한 뒤의 확장이다. 난이도는 상대적인 설계 범위이며 일정 견적이 아니다.

## 첫 시연에 권하는 세 시나리오

1. **처음 연결하기:** 새 프로필 → SSH 키/인증서 검증 → 단계별 연결 진단 → 테이블 조회.
   실패 예제도 보여준다. 잘못된 서버를 거부하고 GUI를 종료하지 않고 수정할 수 있어야 한다.
2. **운영 SQL 작업하기:** 운영 읽기 전용 연결 → 조회 → 느린 SELECT 취소 → 결과 파일 저장 →
   허용된 테스트 DB에서 변경 검토 및 롤백. 화면의 '취소'와 서버의 실제 중단을 함께 확인한다.
3. **복원 신뢰 보여주기:** 작은 덤프 생성 → 바꿀 대상 미리보기 → 격리 DB 복원 → 행/값/객체 검증 →
   손상 파일을 다시 입력하면 대상 변경 없이 거부됨을 보여준다. 지원되지 않는 객체도 공개한다.

제안 측정값: 첫 조회까지 걸린 시간, 안내 없이 완료한 비율, 취소 확인 시간, 최대 메모리,
복원 후 불일치 건수, 실패 후 사용자 도움 요청 횟수. 수치는 아직 측정하지 않았다.
후보 목표는 기준 데이터셋/환경을 정한 뒤 합의해야 하며 임의의 성능 보장은 하지 않는다.

안전 복원과 직접 연결창 응답성은 배포했다. 다음은 연결 보안, 남은 연결 경로,
실제 SQL 취소·결과 제한, 보존된 백업의 정리·복구 검토다. 반복 백업·이관 수요가
관찰되면 P1-3 작업 목록을 이어서 진행한다. 먼저 대표 사용자 3~5명에게
위 과제를 수행하게 하고 막힌 단계와 반복 작업을 관찰한다. 엔진 추가, AI SQL 생성, 협업 서버,
복잡한 라이선스/결제 계층은 이 사용 흐름의 성공률과 수요를 확인한 후 재평가한다.

## 외부 참고와 해석

- [DataGrip 쿼리 실행](https://www.jetbrains.com/help/datagrip/run-a-query.html)은 서버 쿼리 취소와
  연결 해제의 차이, 실행 결과의 파일 저장을 설명한다. 단순 취소 버튼보다 실제 서버 동작을
  검증해야 한다는 기준에 참고했다.
- [DataGrip 연결 설정](https://www.jetbrains.com/help/datagrip/configuring-database-connections.html)은
  연결 단위 읽기 전용 설정을 설명한다. 운영 작업 정책 후보의 참고이며 TunnelForge 구현 보장은 아니다.
- [DBeaver 작업 관리](https://dbeaver.com/docs/dbeaver/Task-Management/)는 데이터 전송·백업 등의
  설정을 작업으로 관리하는 흐름을 설명한다. 재사용 작업의 제품 가치에 대한 참고다.
- [DBeaver 백업·복원](https://dbeaver.com/docs/dbeaver/Backup-Restore/)은 native client 도구를 사용한다.
  TunnelForge는 저장소 정책대로 Rust Core 소유권을 유지해야 하므로 구현 경로를 그대로 복제하지 않는다.

경쟁 제품에 기능이 존재한다는 사실은 우리 고객의 구매 수요나 구현 우선순위를 입증하지 않는다.
우선순위는 코드의 위험과 사용자 과제에 대한 제안이다. 위 구현 상태 외의 후보는 아직 완료되지 않았다.
